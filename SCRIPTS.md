## data_prep.py

```
usage: data_prep.py [-h] [-q] [-d {financial,macro,all}] [--series SERIES]
                    [--force] [--extend] [--aligned-pair ALIGNED_PAIR]
                    [--skip-eu] [--countries COUNTRIES] [--skip-fingerprints]

Stage 1 — data prep. Download, transform, window, fingerprint.

options:
  -h, --help            show this help message and exit
  -q, --quiet           only print the final result line
  -d, --dataset {financial,macro,all}
                        which family to prepare (default: all)
  --series SERIES       restrict to these series, comma separated (e.g.
                        SP500,Bitcoin). Default: all in the catalog
  --force               re-download instead of reading data/raw/*_raw.csv
                        (replaces the whole file, including the days the paper
                        uses)
  --extend              financial: add the days between config
                        data.financial_start and the start of each cached
                        file; the rows already there are kept byte for byte,
                        and nothing changes if Yahoo's overlap differs
  --aligned-pair ALIGNED_PAIR
                        pair to date-align into aligned_windows_real.pkl
                        (default: SP500,Bitcoin)
  --skip-eu             macro only: skip the Eurostat download
  --countries COUNTRIES
                        macro only: EU countries (default: DE,FR,IT)
  --skip-fingerprints   skip the stylized-fact fingerprints (faster; nb_08
                        needs them)

Stage 1 — data prep. Download, transform, window, fingerprint.

Examples
--------
    # everything (financial + macro), using cached raw CSVs where present
    python scripts/data_prep.py -d all

    # just the financial series
    python scripts/data_prep.py -d financial

    # add the earlier history (config data.financial_start) in front of the cached files
    python scripts/data_prep.py -d financial --extend

    # only two series, forcing a fresh download
    python scripts/data_prep.py -d financial --series SP500,Gold --force

    # macro, US only (skip Eurostat — no API key needed for FRED cache hits)
    python scripts/data_prep.py -d macro --skip-eu

    # align a different real pair for the classifier's input
    python scripts/data_prep.py -d financial --aligned-pair SP500,Gold

Writes to data/raw/ (downloads) and data/processed/ (transformed.pkl, windowed.pkl,
fingerprints.pkl, aligned_windows_real.pkl, and the _macro variants).
```

## distill.py

```

standardization (which is what makes the student transfer across series) deletes the
scale information those flags need, so asking the student for them is asking for
something it cannot see. That is a design decision, not a limitation to fix.

What this adds over the notebook: a seeded, stratified train/test split, and
best-held-out checkpointing instead of last-epoch. Every accuracy the notebook
prints is training fit; the number here is held out.
```

## prep_real_pairs.py

```
usage: prep_real_pairs.py [-h] [-q] [-p PAIRS] [--engine {python,vadalog}]
                          [--stride STRIDE] [--batch-size BATCH_SIZE]
                          [--deadband DEADBAND] [--date-from DATE_FROM]
                          [--date-to DATE_TO] [--seq-len SEQ_LEN]
                          [--lags LAGS] [--no-lags] [--keep-old] [--no-macro]
                          [--no-fit-thresholds] [--batches-only]
                          [--skip-recalibrate]

Stage 4b — real pairs. Prepare and label real market pairs end to end.

This is the multi-pair path:
a rule confirmed on ONE pair may be an accident, whereas the same rule holding for
equity-crypto and failing for equity-gold IS the finding. So this script takes
several pairs at once and gives each its own predicate set on the real timeline.

Two tracks, mirroring the notebook:

  --engine python    (Track A, fast) fit thresholds, then label every pair in
        Python. Seconds. Validated against the reasoner at 96.5% regime agreement.
  --engine vadalog   (Track B, slow) fit thresholds, build disjoint-block batches,
        run the reasoner over them (cached + resumable), then rescore by dominance.
        Hours to days, but the labels are the declarative ones.

Financial or macro, same command. A pair is two series of the SAME frequency:

    -p sp500_gold                          financial x financial (daily, 50-day windows)
    -p US_Inflation:US_Unemployment        macro x macro (monthly, 12-month windows)
    -p DE_Inflation:IT_Inflation           cross-country macro

Window length and stride come from the series' configured frequency, so nothing
needs saying on the command line. Use the colon form for macro (their names contain
underscores); the underscore form still works and is resolved against the known
series list, so `us_inflation_us_unemployment` parses correctly too.

Mixing frequencies (SP500 x US_Inflation) is refused with an explanation — that is
the T7 macro-conditioning template, a different computation.

options:
  -h, --help            show this help message and exit
  -q, --quiet           only print the final result line
  -p, --pairs PAIRS     comma-separated pairs. Underscore form (sp500_gold) or
                        colon form (US_Inflation:US_Unemployment). Both sides
                        must share a frequency
  --engine {python,vadalog}
                        python = fast validated bypass (default); vadalog =
                        the reasoner (slow, cached, resumable)
  --stride STRIDE       take every Nth window (default: real_pairs.stride in
                        config, 1)
  --batch-size BATCH_SIZE
                        window pairs per reasoner batch (default: 25)
  --deadband DEADBAND   dominance margin in percentage points. Default comes
                        from configs/config.yaml labels.deadband — the same
                        value the reasoner receives as ${Deadband}
  --date-from DATE_FROM
                        first date (default: real_pairs.date_from in config,
                        2015-01-01). For monthly macro pairs pass a wider
                        range, e.g. 1996-01-01
  --date-to DATE_TO     last date (default: real_pairs.date_to in config)
  --seq-len SEQ_LEN     window length (default: from the pair's configured
                        frequency — 50 for daily, 12 for monthly, 8 for
                        quarterly)
  --lags LAGS           python engine: lead-lag predicates at these lags, e.g.
                        1,2,3 (default: real_pairs.lags in config, 1-5;
                        'config' = the same)
  --no-lags             python engine: skip the lead-lag predicates (T4/T4b
                        then report missing predicates)
  --keep-old            python engine: don't move the pair's previous label
                        folder aside first (default: move it to
                        data/processed/_stale/)
  --no-macro            python engine: don't recompute the macro state
                        (real_pairs.macro_states) after labelling
  --no-fit-thresholds   reuse the existing thresholds/*.csv
  --batches-only        vadalog track: write the batch CSVs and stop
  --skip-recalibrate    vadalog track: don't rescore by dominance afterwards

Stage 4b — real pairs. Prepare and label real market pairs end to end.

This is the multi-pair path:
a rule confirmed on ONE pair may be an accident, whereas the same rule holding for
equity-crypto and failing for equity-gold IS the finding. So this script takes
several pairs at once and gives each its own predicate set on the real timeline.

Two tracks, mirroring the notebook:

  --engine python    (Track A, fast) fit thresholds, then label every pair in
        Python. Seconds. Validated against the reasoner at 96.5% regime agreement.
  --engine vadalog   (Track B, slow) fit thresholds, build disjoint-block batches,
        run the reasoner over them (cached + resumable), then rescore by dominance.
        Hours to days, but the labels are the declarative ones.

Financial or macro, same command. A pair is two series of the SAME frequency:

    -p sp500_gold                          financial x financial (daily, 50-day windows)
    -p US_Inflation:US_Unemployment        macro x macro (monthly, 12-month windows)
    -p DE_Inflation:IT_Inflation           cross-country macro

Window length and stride come from the series' configured frequency, so nothing
needs saying on the command line. Use the colon form for macro (their names contain
underscores); the underscore form still works and is resolved against the known
series list, so `us_inflation_us_unemployment` parses correctly too.

Mixing frequencies (SP500 x US_Inflation) is refused with an explanation — that is
the T7 macro-conditioning template, a different computation.

Examples
--------
    # fast path, three pairs
    python scripts/prep_real_pairs.py -p sp500_gold,sp500_nasdaq,sp500_bitcoin

    # macro pairs
    python scripts/prep_real_pairs.py -p US_Inflation:US_Unemployment
    python scripts/prep_real_pairs.py -p DE_Inflation:IT_Inflation,DE_GDP:IT_GDP

    # reasoner path
    python scripts/prep_real_pairs.py -p sp500_gold --engine vadalog

    # only build the batch CSVs now, run the reasoner later/elsewhere
    python scripts/prep_real_pairs.py -p sp500_gold --engine vadalog --batches-only
    python scripts/label.py -p sp500_gold --track real --engine vadalog

    # tighter subsampling and a wider dead band
    python scripts/prep_real_pairs.py -p sp500_gold --stride 5 --deadband 8

Writes:
    thresholds/tau.csv, thresholds/qlow.csv        (fitted on the TRAIN period)
    real_pairs_batches/<pair>_batch_NNN.csv        (vadalog track only)
    real_pairs_results/                            (reasoner predicate CSVs)
    real_pairs_regime_py/<pair>/                   (python track output)
    real_pairs_regime_reasoner/<pair>/             (recalibrated reasoner output)

Next step: `generate_rules.py --source py -p <pair> --score --ci`.
```

## generate_rules.py

```
usage: generate_rules.py [-h] [-q] [--source {py,reasoner,classifier}]
                         [-p PAIRS] [-t TEMPLATES] [--ground] [--ci]
                         [--pct PCT] [--max-w MAX_W] [--max-gap MAX_GAP]
                         [--score] [--in-sample] [--breaks] [--out OUT]
                         [--tag TAG] [--labels-dir LABELS_DIR]
                         [--list-templates] [--list-pairs]

Stage 8 — rule generation. Fit the template constants and emit DatalogMTL rules.

Label source — the templates don't care which produced the facts, the CSVs are identical:

    --source py          real_pairs_regime_py/<pair>/     exact Python labeler (default)
    --source reasoner    real_pairs_regime_reasoner/<pair>/  Vadalog, recalibrated
    --source classifier  real_pairs_regime_classifier/<pair>/  the distilled classifier
                                                            (regimes predicted, flags copied)

Pairs: name them, or use `all` for every pair labelled under that source.

Grounding: rules are rendered with VARIABLES (X, Y) by default since 2026-08-05,
reversing the 2026-07-31 grounding decision.

The reasoning: syntax and evidence are different things. A rule is a logical object and
carries variables; WHICH ground pairs satisfy it is an empirical question answered by the
per-pair scores in the results table, not by baking one pair into the rule text. That also
turns the gold / bitcoin / nasdaq contrast into support and non-support for ONE rule,
rather than three unrelated single-pair claims.

The original worry — "fake generality", asserting something about pairs never examined —
is answered by reporting every pair the frozen rule was evaluated on, including the ones
where it fails. `--ground` restores the old behaviour.

options:
  -h, --help            show this help message and exit
  -q, --quiet           only print the final result line
  --source {py,reasoner,classifier}
                        which labelling produced the facts (default: py)
  -p, --pairs PAIRS     pairs to mine, comma separated, or 'all' (default:
                        all)
  -t, --templates TEMPLATES
                        templates to run (default: all registered)
  --ground              render with the actual series names instead of
                        variables X,Y. OFF by default since 2026-08-05: a rule
                        is a logical object and carries variables; which
                        ground pairs satisfy it is reported by the per-pair
                        scores, not by baking the pair into the syntax

                        Resamples condition EPISODES where there are enough of
                        them, otherwise 50-day BLOCKS within them — and
                        reports which was used, because the test period often
                        holds a single episode and an interval built from
                        blocks of one event is weaker evidence than it looks
  --pct PCT             percentile for duration templates T5/T6 (default: 25)
  --max-w MAX_W         upper end of the w grid (default: config rules.max_w,
                        25)
  --max-gap MAX_GAP     T6: largest gap between the two regimes (default:
                        unlimited)
  --out OUT             results table (default: results/rules.csv for --source
                        py, results/rules_<source>.csv otherwise)
  --tag TAG             suffix for the output file: rules_<tag>.csv. Defaults
                        to the source for any source other than py, so
                        --source classifier writes rules_classifier.csv and
                        never replaces rules.csv. Ignored if --out is given
                        explicitly

                        read this --source's label folders from DIR instead of
                        the default (e.g. a candidate classifier's infer.py
                        --out-root); use with --tag so the paper's rules files
                        are not touched
  --list-templates
  --list-pairs

scoring (R1):
  --score               compute temporal confidence: |condition AND
                        conclusion| / |condition|, counting condition-days
                        only
  --in-sample           with --score, score over the whole timeline instead of
                        fitting on train and scoring on test. Quick look only
                        — the constants were fitted on that same data, so it
                        is not a result
  --breaks              also print confidence per calendar year (R2 break
                        detection)

Stage 8 — rule generation. Fit the template constants and emit DatalogMTL rules.

Label source — the templates don't care which produced the facts, the CSVs are identical:

    --source py          real_pairs_regime_py/<pair>/     exact Python labeler (default)
    --source reasoner    real_pairs_regime_reasoner/<pair>/  Vadalog, recalibrated
    --source classifier  real_pairs_regime_classifier/<pair>/  the distilled classifier
                                                            (regimes predicted, flags copied)

Pairs: name them, or use `all` for every pair labelled under that source.

Grounding: rules are rendered with VARIABLES (X, Y) by default since 2026-08-05,
reversing the 2026-07-31 grounding decision.

The reasoning: syntax and evidence are different things. A rule is a logical object and
carries variables; WHICH ground pairs satisfy it is an empirical question answered by the
per-pair scores in the results table, not by baking one pair into the rule text. That also
turns the gold / bitcoin / nasdaq contrast into support and non-support for ONE rule,
rather than three unrelated single-pair claims.

The original worry — "fake generality", asserting something about pairs never examined —
is answered by reporting every pair the frozen rule was evaluated on, including the ones
where it fails. `--ground` restores the old behaviour.

Examples
--------

    python scripts/generate_rules.py --source py -p sp500_gold,sp500_bitcoin --score
    python scripts/generate_rules.py --source py -p all -t T1_safeHaven,T5_hedgeHorizon
    python scripts/generate_rules.py --source classifier -p sp500_bitcoin
    python scripts/generate_rules.py --list-templates
    python scripts/generate_rules.py --list-pairs --source py

    python scripts/generate_rules.py --source py -p all --score --ci     # the paper's run

Writes results/rules.csv for --source py, results/rules_<source>.csv otherwise (one row
per template x pair, including rejected ones — "the rule does not hold for this pair" is a
result, and the contrast between pairs that pass and fail is itself a finding).

With --score: constants fitted on the train period, frozen, and scored on train and test
(confidence, baseline, lift; --ci adds the bootstrap interval on the test lift).
Verification against the engine is the next step: verify_rules.py.
```

## relabel.py

```
usage: relabel.py [-h] [-q] --results RESULTS [-o OUT_DIR]
                  [--deadband DEADBAND] [--no-copy] [--all-tags]

Re-derive the correlation regime from percentages the reasoner already wrote.

options:
  -h, --help            show this help message and exit
  -q, --quiet           only print the final result line
  --results RESULTS     folder of reasoner output to relabel (e.g.

  --all-tags            keep non-numeric batch tags. Default skips them:
                        batched_results holds a stray *_test.csv set that

                        values, which puts two contradictory regimes on the
                        same window

Re-derive the correlation regime from percentages the reasoner already wrote.

Replaces the two ABSOLUTE cuts in preLabeling.vada (same% > 55 / diff% > 45) with
RELATIVE DOMINANCE (score = same% - diff%, compared against a deadband). Runs no
reasoning: the concordance was already computed, only the threshold applied afterwards
is being changed. 21 batches take about a second.

Why: on real daily data the absolute bars are effectively unreachable — measured max
diff% is 32 against a bar of 45 — so isNegativeCorrelation never fires and every real
window comes out "no correlation". A classifier distilled against that learns a
degenerate function. See tslearning/labeling/relabel.py for the full argument.

copied through, so distill.py and eval.py read it via --results with no other change.

    python scripts/relabel.py --results data/processed/batched_results

    # the real test set (what fidelity is measured against)
    python scripts/relabel.py --results data/processed/real_test_results

    # try a different deadband
    python scripts/relabel.py --results data/processed/batched_results --deadband 5
```

## timing_table.py
